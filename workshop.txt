title=[B41] Daily Rewards
description=[h1]Daily Rewards[/h1]
description=
description=Give players a polished [b]reward calendar[/b]: sequential daily drops, streak milestones with optional repeatable tiers, missed-day rules you control, and an [b]Admin View[/b] that edits JSON-backed config entirely in-game. Everything lives behind the [b]Dock Menu[/b] entry provided by [b]ElyonLib[/b].
description=
description=[h1]How players use it[/h1]
description=[list]
description=[*]Open [b]Daily Rewards[/b] from the [b]Dock Menu[/b] ([b]ElyonLib[/b]) floating button ([i]Daily Rewards[/i]; works in singleplayer too, needs to be configured first).
description=[*]Inspect the reward-day grid - see what is claimed, claimable today, upcoming, or still locked behind streak rules.
description=[*]Claim eligible [b]daily[/b] days and unlocked [b]streak[/b] rewards from the Player View.
description=[*]Server validation runs on claim - cheating clients cannot spoof rewards ahead of schedule.
description=[/list]
description=
description=[h1]Reward types[/h1]
description=Each calendar row may bundle any mix of these (all enforced on the server when claimed):
description=[list]
description=[*][b]Items[/b] - type + stack count ([i]supports standard item identifiers such as [/i]Base.Apple[i]).[/i]
description=[*][b]XP[/b] - any skill/perk plus positive or negative amounts.
description=[*][b]Traits[/b] - adds a trait when valid; skips if already owned or if it clashes with incompatible traits already on the character.
description=[*][b]Custom Lua handlers[/b] - integrate via [i]RegisterCustomReward[/i]; [i]see [b]Documentation & custom Lua[/b] below[/i] ([b]README.md[/b] link).
description=[/list]
description=
description=[h1]Documentation & custom Lua[/h1]
description=Full handbook for players, admins, and modders ([b]reward JSON[/b], [b]ModData persistence[/b], and the [b]RegisterCustomReward[/b] API plus copy-paste handler examples):
description=[url=https://github.com/eI1on/pz-daily-rewards/blob/main/README.md][b]README.md on GitHub[/b][/url]
description=
description=[h1]Admin configuration (no hand-editing required)[/h1]
description=Admins get an extra [b]Admin View[/b] tab in the same window:
description=[list]
description=[*]Toggle rewards globally and tune high-level behaviour: missed claims allowed or not, repeatable daily ladder, campaign-style [b]start date[/b] (otherwise each player aligns from first join), depth of historical catch-up windows, preview days ahead, and streak grace after missed calendar days.
description=[*]Build or tweak [b]daily[/b] reward rows ([i]your ordered list[/i]) and separate [b]streak[/b] ladders with optional [b]repeatable[/b] tiers.
description=[*][b]Save All[/b] persists to JSON; [b]Import[/b] / [b]Export[/b] for backups and sharing setups; [b]Reset[/b] restores the mod defaults.
description=[/list]
description=
description=[h1]Singleplayer & multiplayer[/h1]
description=[list]
description=[*][b]Dedicated / hosted servers:[/b] granting, streak math, and ModData-backed player progress all stay authoritative on the host.
description=[*][b]Listen / co-op host:[/b] same authoritative path relative to whoever runs server logic for the session.
description=[*][b]Singleplayer:[/b] fully supported - your local campaign counts as single-player server data.
description=[*]When real-world dates roll forward, eligible players automatically receive an info refresh ([i]"New Daily Rewards are available."[/i] toast).
description=[/list]
description=
description=[h1]Config file[/h1]
description=Saved settings live alongside your usual mod Lua folders as [code]DailyRewardsConfig.json[/code] ([i]"Daily Rewards"[/i] mod context). Prefer the in-game importer if you tweak files manually - malformed JSON rejected by the importer shows a sensible status hint.
description=
description=[h1]Requirements[/h1]
description=[list]
description=[*][b]ElyonLib[/b] - load it before Daily Rewards. It adds the Dock Menu button for the reward calendar UI, applies the shared theme and layout, and exposes the helpers used for claims, streak math, and server validation.
description=[/list]
description=
description=[h1]Frequently asked questions[/h1]
description=
description=[h2]Does it need a new save?[/h2]
description=No - add it anytime; defaults generate on first use.
description=
description=[h2]Can I migrate rewards between servers?[/h2]
description=Yes - distribute the exported [code]DailyRewardsConfig.json[/code] blueprint; players still retain their own progression per world unless you deliberately wipe ModData elsewhere.
